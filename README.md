# ATHLOS — Athlete Monitoring System

Next.js / TypeScript / Tailwind CSS / Supabase / Recharts を使用した、サッカーチーム向けのコンディション・トレーニング負荷管理アプリです。初期言語は中国語（簡体字）。画面右上で日本語・英語に切り替えられます。

## 開発

Node.js 22 以上（この環境では 24）、npm を使用します。

```bash
cd /workspace/athlete-monitoring-system
npm ci
npm run dev
```

開発モードでSupabase の環境変数が未設定なら、20名・42日分の**架空データのみ**を使ったデモが起動します。デモでの編集は画面内のメモリーに保持され、再読み込みするとリセットされます。実データをデモに入力しないでください。環境変数が設定されるとデモにはフォールバックせず、ログイン画面になります。

## 実装機能

- 日別チームレポート：日付、チーム、ポジション、アラート、選手名・背番号検索、番号・名前・負荷によるソート、1日累積／セッション別切り替え。
- CSV、Excel（.xlsx）、PDF（ブラウザーの印刷→PDF保存）出力。CSVの式インジェクションを防止。
- Morning Wellness、痛み、参加時間、0〜10 RPEの入力。複数セッションと休養・欠席・未参加・リハビリ・未入力を区別。
- セッションの作成・編集・対象選手管理。提出済み回答のある選手の削除を拒否。編集しても実参加時間は維持し、未入力の基準時間だけ更新。
- 個人詳細、週・月・指定期間累積、7日・28日負荷、Monotony、Strain、EWMA、ACWR。
- 日付範囲・選手選択付きグラフ：負荷推移、週間分布、レーダー、選手比較、ポジション比較、疲労と負荷の散布図。
- 管理者用のアラート閾値・尺度方向・ACWR方式設定、チーム作成、選手作成・編集、アカウントの役割割当、スタッフ権限付与・解除、操作ログ閲覧。
- 医療スタッフの許可された選手への医療メモと対応履歴。担当コーチは毎日の痛み申告を確認・代理入力でき、医療メモは医療担当者と管理者に制限。
- PWA manifest・インストール用アイコン。医療データ・認証ページ・APIはService Workerにキャッシュしません。オフライン入力・同期は未実装。

## Supabase 接続

1. このアプリ専用の空のSupabaseプロジェクトを用意し、SQL Editorで [supabase/install.sql](supabase/install.sql) の全文を1回実行します。初回設定済みのプロジェクトには、`supabase/migrations/` の未適用分だけを番号順に適用してください。Supabase CLIで管理する場合は `supabase db push` を使用し、初回一括ファイルとの二重適用を避けてください。
2. `.env.example` を参考に、環境設定または未追跡の `.env.local` に以下を設定します。
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`（公開可能な publishable key。service role key は使用しません）
3. Authの確認メールと公開URLの `/auth/callback` リダイレクトを設定します。
4. 公開URLで最初の管理者アカウントを作成し、メール認証後に組織名・チーム名を入力します。UUIDを手作業で登録する必要はありません。
5. 設定画面で選手を作成し、「選手・スタッフを招待」から本人用リンクを発行します。携帯やメールがない選手は招待せず、担当コーチが代理入力します。
6. 役割ごとの実アカウントでログインして、別端末からの保存と更新を確認します。

ブラウザーには公開キーだけを渡し、サーバーAPIもログインユーザーのCookieと公開キーで動作します。service role によるRLSの迂回はありません。API側で入力を検証し、DB側ではRLS・CHECK制約・関連付けトリガー・原子的RPCが改ざんを防ぎます。

### 権限モデル

| 役割 | 閲覧 | 書き込み |
| --- | --- | --- |
| Administrator | 自組織の全チーム・選手・医療・監査 | 組織設定、チーム、選手、役割、権限、セッション、Wellness、RPE、医療メモ |
| Coach | 明示的に許可されたチームの選手、Wellness、セッション、負荷 | 担当チームのセッション、参加記録、Wellness・毎日の痛み申告 |
| Medical Staff | 明示的に許可されたチーム／選手のWellness・痛み・医療メモ | 許可された選手の医療メモ |
| Athlete | 自分の記録と割り当て済みセッションのみ | 自分のWellness・痛み・割り当て済みRPE |

医療スタッフへのチーム単位権限は、そのチームの所属選手全体への許可です。コーチへの個人単位権限は認めず、チーム単位で割り当てます。全ロールを組織境界で分離します。監査ログには操作日時・実行者・対象キーを保存し、医療メモや測定値そのものを複製しません。チーム追加時に既存所属は保持されます。所属の終了日管理は将来の拡張事項です。

## 負荷計算規約

- Session load = 実参加時間（分）× RPE。RPE=0は有効です。
- Daily load = 当日の全割り当てセッションの合計。1件でも未提出・欠測なら **null**。参加記録のない日は欠測であり0にしません。休養日を記録するには `Other` / 0分のセッションを作り、参加状態を `rest` にします。
- 週は月曜〜日曜、月は暦月。週・月・指定期間累積は既知分と欠測日数を併記。週間グラフの完全累積値は欠測があれば表示しません。チーム平均は測定済み選手のみが分母です。
- Rolling 7/28 = 連続した暦日の合計。必要な窓の履歴が不足・欠測ならnull。
- Monotony = 7日平均 ÷ 7日の母標準偏差。ゼロ負荷日を含み、標準偏差0ならnull。
- Strain = 7日累積 × Monotony。
- EWMA: λ = 2/(N+1)、最初の観測で初期化。表示対象までの連続42日を使用し、最低N日必要。窓に欠測があればnull。
- ACWR coupled = (直近7日合計/7) ÷ (直近28日合計/28)。uncoupledは慢性負荷に直近7日より前の28日を使います（計35日必要）。EWMA方式はEWMA7/EWMA28。分母0・履歴不足はnull。
- 既存尺度の変更は保存済みの生値を再変換しません。尺度を変更すると過去の指標の意味も変わるため、運用開始前に確定してください。
- アラートは測定値と設定閾値を表示し、元データから都度再計算します。体重と睡眠の質は前回記録と比較、疲労の個人基準は過去7件、新しい痛みは過去7日、負荷急増は直前7暦日の完全な平均値と比較します。閾値設定は `organizations.settings` が正です。`alert_rules` / `alert_events` は将来のアラート履歴保存用スキーマであり、現状のUIはイベント履歴を蓄積しません。
- **ACWRを含む負荷値は単独の傷害予測ではありません。**

初期の日付基準は Asia/Shanghai、日付はDBの `date`、医療メモ・監査は `timestamptz` です。組織ごとのタイムゾーン切替UIは未実装です。

## セッション入力・フラッグ・代理取り込み

選手は日付を選び、その日に割り当てられたセッションのカードを選択してRPEと実参加時間を入力します。朝・午後・夕方の3部練でも各回を独立して保存します。Wellnessは1日1回です。セッションを切り替えても別の選手やセッションの下書き・参加状態を引き継ぎません。

一覧・個人詳細・グラフは赤／黄／基準内／データ不足を文字と色で区別します。管理者設定で、睡眠・疲労・痛み・1日負荷の黄色基準と赤色基準を変更できます。各表示には測定値と基準値を示し、個人の負荷グラフには基準線を表示します。チーム平均や週間合計に1人分の1日基準を当てはめません。これは確認の優先度を示し、傷害の診断・予測ではありません。

レポートの「一括取り込み」から、管理者・担当コーチが代理でセッション別RPEを入力できます。Morning Wellnessも管理者・担当コーチが代理取り込みできます。

1. 画面からExcel（.xlsx）またはCSVテンプレートをダウンロードします。
2. **1行＝1選手・1日・1セッション**で入力します。3部練は3行に分けます。日合計負荷の直接取り込みはせず、時間×RPEから再計算します。
3. ファイルを選択するか、Excel／Google Sheetsの列名を含む範囲をコピーして貼り付けます。
4. プレビューで選手・日付・セッション・入力値とエラー行を確認します。未登録選手、対象外セッション、重複、範囲外数値がある場合は保存できません。
5. 提出済み記録は初期設定で保持します。修正が必要なときのみ、上書きチェックを明示的に選択して保存します。DB側では一括処理を1トランザクションで実行し、失敗した場合は全件をロールバックします。

テンプレートの列名とISO日付（YYYY-MM-DD）を使用してください。XLSXの先頭シートにある値を読み込み、数式・マクロ・外部リンクは受け付けません。最大500行・2MBです。Google Sheetsとの自動同期や、任意形式の旧Wuxiシートの自動変換は含みません。Wellness取り込みでは既存の痛み記録を削除しません。

既存のSupabaseプロジェクトには、追加の `202611030004_bulk_import.sql` と `202611030005_validation.sql` を順に適用してください。後者は、コーチの担当外チームのセッション記録閲覧を防ぎ、直接DBに書き込む場合もWellness尺度を検証します。

前回までの検証：型チェック・本番ビルド、単体25件・ブラウザー操作9件・PostgreSQLの権限／整合性56項目が成功。実際のSupabaseプロジェクトでのログイン・メール・ネットワーク接続は、接続設定が未提供のため未検証です。

追加の006マイグレーションで、招待リンク、初期組織の作成、コーチのWellness代理入力に対応します。本番で設定不足の場合は入力を受け付けません。担当スタッフのデータは60秒ごとに同期します。

セッション別入力表：トレーニング予定の各セッションから、その対象選手全員のCSV／Excel入力表を出力できます。未提出のRPEは空欄で、記入後に同じセッションへ取り込みます。pendingでRPEが空欄の行は未提出として残し、RPE=0は有効な回答として保存します。既存の回答は初期設定で保護し、別セッションのファイルはセッション限定取り込みで拒否します。
